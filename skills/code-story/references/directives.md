# story.md format

`story.md` is Markdown with YAML front matter. Prose is ordinary Markdown (CommonMark plus tables; raw HTML allowed). Code enters only through **directives** (lines starting with `@`) and is laid out with **blocks** (`::: name … :::`). Directives and block markers start at column 0 and take a whole line.

## Front matter

```yaml
---
title: PR 23 story                 # browser tab title; optional
map:
  title: Request flow              # heading of the story map
  subtitle: From token to permission check
traces:                            # values a reader can follow across frames
  user id: [user_id, USER_ID, get_current_user_id]
  issuer: [OAUTH_ISSUER, oauth_issuer]
exclude:                           # leave files out of coverage; reason required
  - path: "migrations/*"
    reason: generated by the ORM
include: ["tests/test_auth.py"]    # bring a default-excluded file back into coverage
---
```

- A trace is a name and the identifiers that spell it. Each identifier matches whole words in the rendered code. Pick the 3–6 values the change is really about. A trace that never matches warns.
- Globs without `/` match the file name in any directory; with `/`, the whole path, and `*` crosses directories.
- Excluded files land in the generated **Not in story** appendix, grouped (Tests, Lockfiles, Generated, Left out on purpose) with your reason. Don't write that appendix yourself.

## Title, hero, chapters

```markdown
# Authenticate with the company's authorization server

One or two paragraphs: what changes and why it matters. They become the hero.

## What a token carries {#token map="The token" where="Arrives with every tool call"}

## Also changed {#also .appendix where="Docs, packaging"}
```

- `#` is the story title. Only prose and `::: sketch` blocks go between it and the first chapter.
- Each `##` is a chapter, numbered in order by the build. Refer to other chapters by name in prose, not by number. Attributes in `{…}`: `#id` (stable anchor; defaults from the map label), `map="…"` (short label on the map; defaults to the heading), `where="…"` (when or where this part runs, shown under the label on the map), `.appendix` (unnumbered, listed under the map's appendix).
- `###` and deeper are ordinary Markdown headings inside a chapter.

## Directives

Hunk ids come from `index`/`show`. They are positional (`#h3` is the file's third hunk), so after the change moves (a push, more edits, a re-index), an id can name different code, which the build reports as a changed anchor, or a hunk can get a new id, which it reports as unknown. Line numbers on cards are always **new-side** numbers, the ones in `show`'s `new` column or the file at head (in a tour, simply the file's lines).

A line of prose that starts with `@` reads as a directive; write `\@` to start it with a literal `@`. Values with spaces or apostrophes go in double quotes: `title="it's the key"`.

### `@diff`

```
@diff src/auth.py#h1
@diff main.py#h1 main.py#h2
@diff src/env.py#h1 rows=13-23 id=env title="EnvModel"
```

- One file per `@diff`. The second line shows several hunks of one file in one frame. Several hunks render as one frame with "lines a–b unchanged" gaps; list them in file order. To show them in another order, use one `@diff` each.
- `rows=a-b` shows part of a single hunk, counted as in `show`'s `row` column. Use it to split one hunk across chapters; changed rows you leave out still need a home somewhere else; context rows don't.
- `id=` names the frame (letters, digits, `-`, `_`; starts with a letter). `title=` replaces the enclosing symbol in the frame header. That symbol is git's hunk header: the nearest definition above where the hunk starts, so a hunk that adds a class or function under another one shows its neighbour's name. Set `title=` when it misleads.

### `@ctx`

```
@ctx tests/test_asgi_auth.py@head 47-70 id=tok title="signed_token, the fixture every auth test signs"
@ctx src/access.py@base 108-124
@ctx src/access.py@head 43
```

Unchanged code at head or at the merge-base, marked Unchanged. Use it for context one hop out: callers, consumers, the fixture that shows a shape, the code a removed line used to call. Any file in the repo works, changed or not. Read the exact lines with `show path@head:a-b` first (`show` also takes `path@head a-b`, and `@ctx` takes `path@head:a-b`); line numbers from other tools are easy to get one off.

### `@ripple`

```
@ripple src/server.py#h3 src/server.py#h4 src/server.py#h5 label="3 more tools log the caller the same way"
```

The same mechanical change at many sites: the first hunk renders as a frame, the rest fold into an expandable "N more sites". Takes `id=`, `title=`, `label=`.

### `@also`

```
@also docs/adr/0001-oauth.md note="Why OAuth becomes the only login"
```

A collapsed file row with its whole diff inside, for appendices. It covers the file's changes. Use it for files that belong to the change but not to the walk: docs, packaging, version bumps.

### `@tree`

```
@tree . depth=1
@tree src/handlers depth=2 id=handlers title="One module per endpoint"
```

A directory at head as git has it: subdirectories with their file counts, files with their line counts (their size above 2 MB), `depth=` levels deep (default 2). `.` is the repo root. Files a frame on the page shows are links to that frame. Use it when the layout itself tells the reader something; it's most at home in a tour. Takes `id=`, `title=`, `depth=`.

In a tour (`index --tour`) there's no diff: only `@ctx path@head` and `@tree` work, and there's no coverage check. See [`tour.md`](tour.md).

## Blocks

Blocks open with `::: name args` and close with a bare `:::`. They nest; close the inner one first. Code fences inside blocks work as usual. A card, branch or note holds anything a chapter holds (prose, directives, notes, forks), except headings.

Ids are one namespace across the page: a chapter's `{#id}`, a frame's `id=`, and the page's own ids. Give frames ids that say what they show (`id=past-cte`), distinct from chapter ids.

### `step` and `card`: code with evidence beside it

```markdown
::: step
@diff src/auth.py#h1 id=auth

::: card 15,21
The issuer and the key replace the old identity provider's signing keys. The key arrives as the PEM text itself.

@diff src/env.py#h1 rows=13-23
:::

::: card 15
In Terraform, the key comes from the secrets manager

@diff terraform/stages/prod/main.tf#h1
:::
:::
```

- A step holds exactly one code directive (the spine), then only cards. The cards sit in a lane to the right of the code, each wired to the lines it supports.
- `::: card LINES` names the spine's lines it supports: `57`, `56-57`, `15,21-23`. The build checks that the spine shows them. Several cards can point at the same line.
- A card's first paragraph is its reason, one line. Whatever follows (code directives, notes, prose) is the evidence.
- Use a step only when each card supports a specific line. Supporting material without a line to point at goes in the chapter flow.

### `fork` and `branch`: paths that leave the main flow

```markdown
::: fork Rejected before the middleware
::: branch No token
A request without a bearer token gets a 401.

@ctx tests/test_asgi_auth.py@head 120-131
:::
::: branch Invalid token
…
:::
:::
```

A bar with one button per branch; each opens in place under the bar. Put a fork at the decision point the branches leave from. A fork holds only branches.

### `note`

```markdown
::: note mismatch The PR description and the code disagree
The description says users are identified by `sub`. The code reads `claims.user_id`.
:::
```

Kinds: `mismatch` (description, docs, code or tests disagree), `question` (something the reviewer should check), `finding` (a problem you found), `external` (a mechanism outside the repo), `symlink` (one file that changes several places), `note` (anything else; also the default when the first word isn't a kind). The text after the kind is the title. `mismatch`, `question` and `finding` are review notes: the reader can hide them with `n`.

### `sketch`

```markdown
::: sketch What callers see
request -> verify(token) -> user id -> permissions
:::
```

Pseudo-code or a diagram in text, framed and labelled "not code from git". Everything inside is shown verbatim. This is the only place for hand-written code-like text: a fenced code block of two or more lines in prose warns.

## Coverage

Every added or removed line in a file that isn't excluded must appear in at least one `@diff`, `@ripple` or `@also`. Repeats are fine. Once a file appears anywhere:

- blank lines, lines whose only change is trailing whitespace, and hunks that only add, drop or reorder whole import statements count as shown (an edited import, or an indentation change, does not);
- Markdown and other docs (`.md`, `.mdx`, `.rst`, `.adoc`), added or deleted files, binaries, symlinks and submodules count as shown as a whole, and so do renames and mode changes without content edits. A renamed or re-moded file with edits still needs its hunks placed.

When the build lists gaps, place each hunk in the chapter it belongs to, put files outside the walk in an appendix with `@also`, or exclude them in front matter with a reason.

## Build messages

| Message | What to do |
|---|---|
| `unknown hunk 'x'; did you mean …` | Use an id from `index` or `show`. |
| `rows=a-b is outside 1-N` | Count rows with `show HUNK`. |
| `id 'x' is already used by …` | Rename one of the two; the message says where the first one is. |
| `card points at line(s) …` | Use new-side numbers the spine shows, or widen the spine. |
| `'::: step' needs exactly one @diff, @ctx or @ripple` | One spine per step; move the rest into cards or the chapter. |
| `coverage: these changes aren't in the story` | See Coverage above. |
| `the code under these anchors changed` | Re-read with `show`, update the named chapters, build with `--accept`. It applies only to a build that succeeds. |
| `the working tree changed since index` | Run `index` again. |
| `list a file's hunks once each, in file order` | Reorder the ids, or split into one `@diff` per hunk. |
| `id … is taken by the page itself` | Pick another id; `files`, `side`, `map`, `help`, `trace-pop`, `syn-pick`, `not-in-story` and ids starting `fd-` or `br-` belong to the page. |
| `a tour has no diff` / `a tour has no base` | Use `@ctx path@head a-b` or `@tree`. |
| `hand-typed code block` (warning) | Replace with a directive, or use `::: sketch`. |
